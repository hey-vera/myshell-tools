# The Adaptive Confidence Brain — the keystone that thinks like a professional

READ-ONLY design. No code changed. Repo: `/home/runner/workspace` (myshell-tools;
orchestrates claude/codex/opencode provider CLIs over the user's OAuth subscriptions —
no API keys, no metered services, no embeddings/vector-db). This is the KEYSTONE doc that
unifies `.tmp-vision-partner.md` (the confirm seam), `.tmp-vision-engine.md` (the
multi-goal scheduler) and `.tmp-vision-ux.md` (the progress/confirm UX).

## TL;DR — the owner's vision, grounded

The owner does NOT want a rigid `propose→confirm→execute` form. They want a **SMART
ADAPTIVE TALKER**: when it tries to understand and **confidence is low it KEEPS GOING** —
investigating the codebase, researching online (via subscription CLIs), brainstorming
across models, or reflecting — and only loops the user in when it hits a genuine judgment
call. It narrates as it thinks ("let me look at how your feed is built first…"), and when
sure, it just does it.

The good news from grounding this in the code: **the building blocks already exist and are
mostly wired.** What's missing is not the tools — it's the **brain that loops over them**.
Today the engine does ONE pass: `planEngagement` picks an ordered action list, renders it
as *advisory prompt text*, and hands the whole thing to ONE provider run. The model is
told "investigate first, then act" — but the orchestrator never **re-measures confidence
after the investigation** and never **decides again**. There is no loop. That single missing
loop is this design.

The brain is a bounded **assess → act-or-investigate → re-assess** control loop sitting
where `planEngagement` is called today (`orchestrate.ts:320`), turning the existing
one-shot policy into an iterative one that deepens understanding before committing, and
that — once confident — decomposes into the multi-goal scheduler from `.tmp-vision-engine.md`.

## 1. THE CONFIDENCE MODEL — what signals are real, and what "too low to act" means

There are TWO distinct confidence signals in the codebase today, at different points in the
turn. The brain must use BOTH but never conflate them.

### 1a. UNDERSTANDING confidence (pre-execution) — `IntentFrame.confidence`
- `IntentFrame.confidence: 'high' | 'medium' | 'low'` (`intent.ts:58`) — the extractor's
  confidence it **understood the GOAL** (explicitly "not correctness of the work",
  `intent.ts:57`). Populated by the gated model extractor on substantial turns
  (`orchestrate.ts:300-307`), else by `rulesIntentFrame` which assigns confidence purely by
  tier (`intent.ts:336-348`: worker→medium, ic/manager→low) — i.e. the rules frame's
  confidence is a *prior*, not a measurement.
- Derived pure signals over the frame already exist and are exactly the "what kind of
  low-confidence is this?" decomposition the brain needs:
  - `isAmbiguous(s)` (`engagement.ts:147`): low/medium confidence OR a real fork exists.
  - `realForks(s)` (`engagement.ts:142`): count of genuine decision points.
  - `hasGenuineFork(s)` (`engagement.ts:293`): a fork the **code cannot answer** (vision /
    preference / external decision) — the only thing that earns a *question*.
  - `isInvestigable(s)` (`engagement.ts:214`): the turn plausibly concerns code in the
    working dir — ambiguity resolvable by **looking**, not asking.
  - `needsContext(s)` (`engagement.ts:188`) / `needsExternal(s)` (`engagement.ts:313`):
    scored "needs codebase reading" / "needs current external facts".

### 1b. ANSWER confidence (post-execution) — `tier-done.confidence`
- `tier-done.confidence: number | null` (`types.ts:681`) — the model's **self-reported
  confidence in the answer it just produced**, parsed from its output envelope (null when
  unparseable). This already drives the escalation loop: below `policy.confidenceFloor`
  indexed by risk (`types.ts:208`) → escalate a tier / failover. This is the brain
  ALREADY working *inside* one `orchestrate()` call, post-hoc.

### 1c. STAKES + reversibility (the third axis — when low confidence is dangerous)
- `classification.risk` (`'low'|'medium'|'high'|'critical'`) from `decideRoute`
  (`orchestrate.ts:258`).
- `isIrreversible(task)` (`engagement.ts:133`): a conservative-broad lexicon (deploy,
  delete, migrate, publish, force-push, drop table, production…).
- The SAFETY FLOOR already encodes "irreversible ∧ ambiguous → discuss/ask"
  (`engagement.ts:404`).

### The brain's confidence model (composition of the above)
The brain treats confidence as a **3-tuple per turn**, all computed PURE from signals
already in scope — no new model call to measure it:

```
Confidence = {
  understanding:  high | medium | low      // IntentFrame.confidence + isAmbiguous
  groundedness:   grounded | unread        // have we actually read the relevant code/facts yet?
  stakes:         low | high               // risk high/critical OR isIrreversible(task)
}
```

`understanding` and `stakes` are read directly from the existing predicates.
`groundedness` is the ONE genuinely new bit of state the brain tracks: *has this turn
already gathered the context that would raise understanding?* Initially `unread`; flips to
`grounded` after an investigation round runs (see §3). This is what lets the loop know it
already looked and shouldn't loop forever.

**"Too low to act" is a pure predicate** — `confidenceTooLowToAct(conf)`:
- understanding=`low`/`medium` AND the gap is **investigable** AND we are still `unread`
  → too low: **investigate** (raise it ourselves — the owner's "KEEPS GOING").
- understanding=`low`/`medium` AND the gap is a **genuine non-investigable fork**
  (`hasGenuineFork`) → too low, and **not investigable**: this is a real judgment call →
  **reflect+confirm / ask** (loop in the user).
- stakes=`high` AND understanding≠`high` → too low regardless: **reflect+confirm** before
  the irreversible step (the safety floor, promoted from advisory text to an actual gate).
- otherwise → **confident enough to act**.

Honesty rule (hard): the brain NEVER fabricates confidence. If the extractor was skipped /
failed, `understanding` is the rules prior (`low`/`medium`), and the brain treats an
unmeasured understanding on a non-trivial turn as a reason to **investigate**, not to
assume high. `source: 'skipped'|'rules-fallback'` on the frame (`intent.ts:60`) is the
honest provenance the brain branches on.

## 2. THE INVESTIGATION TOOLBOX — real vs not (grounded, subscription-only)

When `confidenceTooLowToAct` says "investigate", the brain marshals one of these. Each is
GROUNDED in code that exists. Each investigation round surfaces as a live GOAL/AGENT in the
multi-goal view (ties to `.tmp-vision-engine.md` + `.tmp-vision-ux.md`).

### 2a. CODEBASE SCRAPING — **REAL, already wired** (`repo-map.ts` + `repo-scan.ts`)
- `buildEnvironmentContext(cwd, nodeRepoScanPort)` (`repo-map.ts`) produces a bounded,
  deterministic ENVIRONMENT/repo-map orientation block: project-type detection, ranked
  most-recently-touched tracked files, git branch/dirty. **NO model call, NO embeddings, NO
  vector DB, regex+heuristics only** (`repo-map.ts:6-7`), capped at `ENVIRONMENT_BLOCK_CHAR_CAP`
  = 2000 chars (`repo-map.ts:37`). The impure reader `nodeRepoScanPort` (`repo-scan.ts:32`)
  is all best-effort git/fs with timeouts (`GIT_TIMEOUT_MS=4000`), degrading to empty on any
  failure.
- It's ALREADY built once per session in the interface (`menu.ts:1753-1763`, memoized) and
  threaded as `deps.environmentContext` (`orchestrate.ts:618`), feeding `repoPresent`
  (`orchestrate.ts:397`).
- **What's new for the brain:** today this is *orientation* (a static map handed to the
  model so its own Glob/Grep starts smart, `repo-map.ts:9-11`). The brain uses it as a
  **confidence lever**: when `understanding≠high` and `isInvestigable`, the brain runs a
  *targeted read pass* — a cheap, sandboxed, read-only `orchestrate()` sub-call whose task
  is "inspect ONLY the files relevant to <goal> and report what you found"
  (the exact `INVESTIGATE_CONTEXT` instruction already exists, `engagement.ts:576`). The
  model's OWN Read/Grep tools do the deep retrieval; repo-map gives it the starting map.
  After it returns, the brain flips `groundedness → grounded` and **re-extracts intent on
  the enriched context** to re-measure `understanding`. THIS is "scrape the codebase to
  raise my own confidence" made real.

### 2b. ONLINE RESEARCH — **REAL but provider-bound** (Codex CLI native web_search)
- Honest finding: there is **no API-key web search, and only ONE provider CLI does it**.
  The Codex adapter enables live web search via the config override `-c tools.web_search=true`
  (`codex.ts:104-115`) — "runs under the user's logged-in subscription — no api key /
  metered service" (`codex.ts:106-107`). Claude/OpenCode adapters ignore the flag.
- The signal is ALREADY plumbed end-to-end: `engagementPlan.actions.includes('WEB_RESEARCH')`
  → `wantsWebSearch` (`orchestrate.ts:329`) → `route()`'s SOFT pre-pass *prefers* a
  search-capable provider (`route.ts:400-425`) → `req.webSearch` set on the provider request
  (`orchestrate.ts:645,699,997,1548`). `needsExternal` (`engagement.ts:313`) is the pure
  gate (explicit "latest/current/look up/recent" only — never research the known).
- **What's new for the brain:** WEB_RESEARCH becomes an investigation ROUND like codebase
  scraping — run when `needsExternal` fires AND understanding is gated on an external fact —
  with the same re-assess-after loop. **Honesty caveat to surface to the user:** if Codex is
  not signed in, web research is unavailable; the brain must say so ("I can't search the web
  right now — only Codex does that and it's not connected — so I'll work from what I know and
  flag the assumption") rather than silently degrade or fabricate a citation.

### 2c. MULTI-MODEL BRAINSTORM — **REAL, default-OFF** (`ensemble.ts` panel)
- `runPanel` (`ensemble.ts:639`) runs N providers CONCURRENTLY on one turn + a cross-vendor
  synthesizer, via the reusable `mergeCandidates` fan-in (`ensemble.ts:573`, `Promise.race`
  over generators). It already emits an up-front honest cost notice ("N quota-consuming
  runs", `ensemble.ts:673-678`) and a typed `phase:'panel'`/`'synthesis'` event
  (`types.ts:641`) the UI renders as "Waiting on N models".
- `planPanel` is **default OFF** (`orchestrate.ts:563`, gated on `policy.panelPolicy` +
  ≥2 providers).
- **What's new for the brain:** when a problem is genuinely **open-ended** (high
  `scopeScore`, `understanding=low`, NOT investigable — i.e. a design/architecture judgment,
  not a lookup), the brain can elect a brainstorm round: run the panel to **cross-examine
  approaches**, then synthesize. This is the "more brainstorming" arm of the owner's vision.
  It is the most expensive lever, so it is **opt-in / high-stakes-gated** (see §5).

### 2d. The toolbox as a uniform shape
The brain treats all three as `InvestigationKind = 'codebase' | 'web' | 'brainstorm'`, each
realized as ONE bounded sub-`orchestrate()`-style run that (a) surfaces as a live goal card,
(b) returns a short findings string, (c) is folded back into the next intent re-extraction.
This uniformity is what makes the loop simple.

## 3. THE ADAPTIVE CONTROL LOOP — the brain's decision policy

This replaces the **single** `planEngagement` call at `orchestrate.ts:320` with a bounded
loop. Crucially it REUSES `planEngagement` as the per-iteration policy — the loop is the new
part, not the policy. It is fluid, not a rigid gate: most turns make ONE pass and either
answer or execute; only genuinely-uncertain turns spend extra rounds.

### Per-turn policy (pseudocode — lives in a new PURE `decideNextMove`, impure loop in orchestrate)

```ts
// PURE core (engagement.ts sibling) — table-testable, no I/O, no model call.
type Move =
  | { kind: 'answer' }                                   // confident, low-stakes → just do it
  | { kind: 'execute' }                                  // confident build → hand to scheduler (§4)
  | { kind: 'investigate'; tool: 'codebase'|'web'|'brainstorm'; narration: string }
  | { kind: 'reflect_confirm'; proposal: PlanProposal }  // judgment call / high stakes
  | { kind: 'ask'; questions: QuestionSet };             // genuine non-investigable fork

function decideNextMove(conf, signals, plan /* = planEngagement(signals) */, state): Move {
  // state = { rounds: number, groundedness, optedOutOfDeepDive: boolean }

  // 0) trivial fast-path — unchanged from today (engagement.ts:158); never loops.
  if (isTrivial(signals)) return { kind: 'answer' };

  // 1) genuine non-investigable fork ALWAYS wins (a real judgment call).
  if (hasGenuineFork(signals) && forkBudget(...) > 0)
     return { kind: 'ask', questions: deriveAskFromForks(frame, plan)! };

  // 2) high stakes + not-fully-understood → reflect & confirm BEFORE acting (safety floor,
  //    promoted from advisory text to a real gate).
  if (conf.stakes === 'high' && conf.understanding !== 'high')
     return { kind: 'reflect_confirm', proposal: proposeFromFrame(frame, plan) };

  // 3) low/medium understanding + investigable + budget left → KEEP GOING (the owner's core ask).
  if (confidenceTooLowToAct(conf) && conf.groundedness === 'unread'
      && state.rounds < MAX_ROUNDS && !state.optedOutOfDeepDive) {
     if (plan.actions.includes('WEB_RESEARCH'))   return inv('web',  'let me check the current docs on that…');
     if (plan.actions.includes('INVESTIGATE_CONTEXT') || isInvestigable(signals))
                                                  return inv('codebase', 'let me look at how that\'s built first…');
     if (scopeScore(signals) >= PLAN_T && conf.understanding === 'low' && !isInvestigable(signals))
                                                  return inv('brainstorm', 'this is open-ended — let me think it through a few ways…');
  }

  // 4) investigated but STILL unsure and it's a judgment call → reflect & confirm.
  if (confidenceTooLowToAct(conf) && conf.groundedness === 'grounded')
     return { kind: 'reflect_confirm', proposal: proposeFromFrame(frame, plan) };

  // 5) confident → build-shaped goes to the scheduler; otherwise just answer.
  return isBuildShaped(signals, plan) ? { kind: 'execute' } : { kind: 'answer' };
}
```

### The impure loop (in orchestrate, around line 320)

```
state = { rounds: 0, groundedness: 'unread', optedOutOfDeepDive: <from partnerStyle/policy> }
frame = <gated extraction>                          // exists today
loop:
  signals = buildSignals(frame, classification, ...)
  plan    = planEngagement(signals)                 // exists today
  conf    = assessConfidence(frame, signals)        // PURE, new (§1)
  move    = decideNextMove(conf, signals, plan, state)   // PURE, new
  switch move:
    answer      → run ONE sequential orchestrate pass (today's path) and finish
    execute     → decompose + hand to runSchedule (§4)
    ask | reflect_confirm
                → yield free terminalQuestion/proposal (zero-token) and RETURN  (reuses a4)
    investigate → narrate (emit notice + a live goal), run ONE bounded read-only sub-pass,
                  capture findings, append to context, RE-EXTRACT frame on enriched context,
                  state.rounds++, state.groundedness = 'grounded', and  ── loop ──
```

### What makes it feel "magical" (and stays honest)
- **Proactive:** it raises its own confidence instead of bouncing every uncertainty back to
  the user. The DEFAULT for an investigable gap is *go look*, not *ask* — exactly the
  existing INVESTIGATE-BEFORE-INTERROGATE principle (`engagement.ts:417-426`), now actually
  iterated rather than only suggested in prompt text.
- **Narrates its thinking:** each investigate round emits a natural one-liner ("let me look
  at how your feed is built first…") via the existing `notice` event (`types.ts:704`) and a
  live goal card. The narration strings come from `decideNextMove` (pure), so they're
  testable and never fabricated post-hoc.
- **Rarely asks; asks sharply when it does:** only `hasGenuineFork` (vision/preference/
  external) reaches `ask`, and the existing generic-menu rejection (`engagement.ts:271-305`)
  guarantees it never asks the order-taker "are you fixing/adding/polishing?" question.
- **Fluid, not gated:** trivial turns short-circuit at step 0; confident build turns flow
  straight to step 5. The loop only spins on genuinely-uncertain, investigable turns.

## 4. UNIFICATION — the brain DRIVES the engine + UX

The brain is the producer; the scheduler (`.tmp-vision-engine.md`) is the executor; the UX
(`.tmp-vision-ux.md`) is the renderer. One coherent system:

1. **Confident understanding → decompose → concurrent goals.** When `decideNextMove`
   returns `execute` on a build-shaped turn, the brain's now-confident `IntentFrame` +
   `WorkContract.roadmap` (seeded by `seedFromIntentAndPlan`, `engagement.ts:492`) is exactly
   the **decomposition input** the engine doc's `planSchedule`/`runSchedule` consumes
   (`.tmp-vision-engine.md §3`). The roadmap items become goal specs; `runSchedule` fans them
   out at `activeLimit` 2–4 over distinct providers.
2. **Investigation goals AND execution goals share ONE rendering path.** Every investigate
   round (§3) and every execution goal emits the SAME `tier-start`(`title`,`risk`) /
   `tier-done` / `notice` CoreEvents the multi-goal reducer + `StatusBlock` already render
   (`.tmp-vision-ux.md §3`). A codebase-scrape round shows as a goal card "◐ Reading how the
   feed is built · 1 agent"; a brainstorm round shows as a panel ("Waiting on 3 models" via
   the existing `phase:'panel'` event). So the user literally watches the brain think — the
   investigation rounds and the work goals stack in the same GOALS panel.
3. **The confirm seam is the brain's `reflect_confirm`/`ask` output.** `.tmp-vision-partner.md`'s
   `proposePlan` directive field + the pre-provider zero-token return (`orchestrate.ts:504`)
   is precisely what `decideNextMove` emits for the `reflect_confirm`/`ask` moves. The brain
   decides WHEN to confirm (a judgment call or high stakes); the partner doc supplies the
   mechanism (`final.questions`); the UX doc supplies the `PlanPanel` y/e/n rendering.
4. **One loop, three docs:** brain = the loop + the confidence model (this doc);
   partner = the confirm/ask primitive the loop calls; engine = the executor the confident
   loop hands off to; ux = the renderer all of them emit into.

## 5. HONESTY + BOUNDS — autonomous investigation must not run away

Autonomous investigation burns quota + wall-clock. The bounds (all enforceable with existing
machinery):

- **Bounded rounds.** `MAX_ROUNDS` (propose **2** by default; 3 for `collaborative`). Mirrors
  the existing depth clamp ∈{0,1,2} (`engagement.ts:454-458`) and the goal-loop
  `DEFAULT_MAX_GOAL_ITERATIONS=8` ceiling (`goal.ts:56`). After `MAX_ROUNDS`, the loop MUST
  exit to `answer`/`execute`/`reflect_confirm` — never investigate again.
- **Confidence-improvement stop condition.** A round must *earn its keep*: if a re-extraction
  after an investigation round does NOT raise `understanding` (or flip an investigable gap to
  grounded), the brain stops investigating and proceeds with a stated assumption + a confirm
  — it does not spin re-reading the same code. (`groundedness` flips to `grounded` after the
  first codebase round so step 3's `=== 'unread'` guard naturally prevents a second identical
  read.)
- **Opt-in for expensive deep dives.** Codebase scrape is cheap (read-only, one IC sub-pass)
  and on-by-default for investigable build turns. **Brainstorm (panel)** is the expensive one:
  gated exactly like `planPanel` is today (default OFF / `policy.panelPolicy` / high-stakes
  preset, `orchestrate.ts:563`), and it emits the up-front "N quota-consuming runs" notice
  (`ensemble.ts:673-678`) before it runs. **Web research** requires Codex signed in; if not,
  the brain says so honestly (§2b) rather than degrading silently.
- **Surface cost honestly (tokens-not-dollars).** Every round's `tier-done` carries real
  measured `inputTokens`/`outputTokens` (`types.ts:686`); `costUsd` stays off the hot path
  (`types.ts:682-683`, the tokens-not-dollars contract). The brain emits a running token tally
  on the goal cards via the existing summaries (`compactGoalsSummary`). It NEVER prints a
  fabricated dollar figure or a fake "confidence %".
- **Cancelable (ESC).** Each investigation sub-pass runs under the turn's `AbortSignal`
  (orchestrate's `streamProvider` checks abort per event, `orchestrate.ts:152,177`); ESC
  aborts mid-round, the loop sees `signal.aborted` and emits a cancel `final`. For the
  scheduler hand-off, the parent/child AbortController fan-out from `.tmp-vision-engine.md §3`
  applies.
- **Web research only via subscription provider tools.** No API-key search path is ever
  added; the ONLY web search is Codex's `-c tools.web_search=true` (`codex.ts:113`). No
  embeddings, no vector DB, no metered service — the whole loop rides `orchestrate()` /
  `route()` / the existing ledger + `authorizeTier` gates; no second router, no bypass.
- **Never fabricate confidence.** `assessConfidence` reads only real signals; a skipped/failed
  extraction yields the honest rules prior and is treated as "investigate", never "assume
  high" (§1).
