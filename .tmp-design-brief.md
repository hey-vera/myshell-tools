## Product vision
myshell-tools is a CLI chat partner over MULTIPLE provider CLIs (Claude, Codex/GPT, etc.), all authenticated by the user's existing **subscription OAuth** (NOT API keys). The north star: **"one chat, automatic, honest"** — the user types intent, the tool auto-picks the right model and the right execution strategy, and is brutally honest about cost/limits. The owner just said: **"auto and frictionless most of the time."**

## HARD GUARDRAILS (violating any = invalid design)
1. Subscription-OAuth auth ONLY. No API keys, no embeddings, no vector DB, no metered/per-call paid services anywhere. Reuse the provider-CLI OAuth machinery only.
2. Cost is QUOTA/RATE-LIMIT on a flat-rate plan, not dollars. So "free" runs still consume the user's plan quota and add latency — honesty about that is mandatory (the partner persona is brutally honest; no "free!" marketing).
3. Behavior-preserving where it counts: this is a working tool with 3497 passing tests. Changes must be gated.

## The two concurrency paths today (both default-OFF, both manual opt-in)
**PANEL** (ensemble.ts, ~996 LOC): runs N signed-in models in PARALLEL, then a synthesizer reconciles them into one answer. Buys cross-vendor DIVERSITY/CORRECTNESS — catches confident-but-wrong single-model answers. Cost: N+1 model runs per hard turn. Trigger today: user sets `panelPolicy: 'hard-turns' | 'always'`; 'hard-turns' runs only on high/critical-risk turns AND >=2 authed providers.

**HEDGE** (hedge.ts, ~901 LOC): races the weak/fast model against the strong/slow flagship — after a delay (default 4s), if the primary hasn't returned, start the flagship in parallel; ship the first ADEQUATE result, cancel the loser. Buys LATENCY HIDING on escalation. Cost: 1 run if primary fast+adequate, else 2 overlapped runs. Trigger today: user sets `hedgePolicy: 'on'`; then fires only on high/critical risk + flagship admittable + >=1 authed provider + a sleep port injected.

They are DISTINCT (correctness vs latency), not redundant. Neither auto-engages today — both need a manual settings flag.

## Existing precedent in the codebase
There is already a `shouldReview(classification, ...)` auto-gate in orchestrate.ts that auto-engages a cross-vendor REVIEWER on hard turns without the user flipping a flag. So "router auto-engages an expensive strategy on high/critical turns" is an established, accepted pattern here. The router already computes: a risk classification (trivial..high/critical), the number of authenticated providers, and flagship admittability per the user's plan/policy.
