**TL;DR**

The biggest quota lever is prompt caching/prefix reuse. This repo builds one large flat prompt string every stateless call: tier persona, injected context, compact history, task. Providers send that string via stdin/temp file, and there is no request-side `cache_control`, `prompt_cache`, or cache breakpoint wiring. The ledger passively stores cache-read tokens when a CLI reports them, but drops Claude cache-write tokens and prices cached input as full-price input. Net: the stable prefix is probably being resent at full token cost on most stateless turns. Given the caps, the avoidable repeat is roughly the persona plus up to 6k chars injected context plus up to 6k chars history, often several thousand input tokens per work/review/panel call.
